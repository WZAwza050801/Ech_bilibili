# 部署与网络（新手必读）

> 这一页讲的是**"能不能跑起来"之外的那一半**：跑在哪台机器上、网络怎么通、额度会不会被烧穿、
> 产物怎么收回来。凡是踩过坑的都在这里，请**在动手部署之前先读完**。
>
> 只想知道怎么在本机跑单期视频，看根 [README](../README.md) 即可；本文面向
> "要把它放到服务器上批量跑" 的读者。

---

## 0. 一分钟看懂：这套东西跑在哪

本项目的批量任务**不在本机跑**，而是「本机 + 服务器」分工。

| 角色 | 典型环境 | 负责什么 | 不负责什么 |
|---|---|---|---|
| **本机** | Windows / macOS / Linux 工作站 | 开发调试、单期试跑、**提供网络出口（梯子）**、产物归档与备份 | 不承担全量批量的 CPU 时间 |
| **服务器** | Linux（实验室集群节点 / 云主机） | **全量批量跑批**（下载 → ASR → LLM 整理 → 渲染），并行多工人 + 断点续跑 | 不一定有外网，不一定能直连 YouTube |

一次完整的批量长这样：

```
[本机] 准备清单/队列 ──scp──▶ [服务器] 多工人并行跑批 ──scp──▶ [本机] 归档 + 备份/网盘
   ▲                                 │
   └──────── 反向隧道（YouTube 必需）──┘
```

实测规模（2026-09，见下文"实测数据"）：两台机器配合，447 期 × 2 个创作者，
约两天跑完，服务器侧产物 320MB + 13MB。

## 1. ⚠️ 头号坑：服务器**够不着 YouTube**（不是配置问题，是网络位置问题）

### 现象

在国内的校园网 / 实验室服务器上，直接从服务器请求 YouTube 会**超时**：

```
$ curl -sI --max-time 10 https://www.youtube.com
curl: (28) Connection timed out        # 连不上，不是 403、不是证书问题
```

实测：国内某高校集群节点上，`youtube.com` 与 `lexfridman.com` **双双超时**，
但 `pypi.org` 正常——说明是**国际出口被限制**，装依赖没问题、拉视频必挂。

**结论：不要把"服务器能上网"当成"服务器能上 YouTube"。** 这是两件事。

### 方案：SSH 反向隧道，让服务器"借"本机的梯子

思路很简单——**本机→服务器**这个方向的连接是通的（你本来就能 SSH 上去），
那就反过来在服务器上开一个端口，把流量穿回本机的代理：

```
[服务器] 127.0.0.1:17890 ──(SSH 反向隧道，本机主动发起)──▶ [本机] 127.0.0.1:12000（梯子/Clash/iKuuu）
```

**本机执行**（保持这个窗口开着）：

```bash
ssh -N -R 17890:127.0.0.1:12000 <user>@<server>
#          ▲     ▲              ▲
#          │     └ 本机代理端口（按你自己的梯子改）
#          └ 在服务器上开的端口（随便挑一个没被占用的）
```

**服务器侧**（或写进它的 `.bashrc` / 启动作业里）：

```bash
export ECHONOTES_YT_PROXY=http://127.0.0.1:17890
# 历史别名 ECHONOTES_YT_PROXY 也可写作 ECH_YT_PROXY / YT_PROXY
```

**验证（在服务器上跑，两条都要过）**：

```bash
curl -sI --max-time 15 -x http://127.0.0.1:17890 https://www.youtube.com | head -1
# 期望：HTTP/2 200
python -c "import yt_dlp,sys; print(yt_dlp.YoutubeDL({'proxy':'http://127.0.0.1:17890'}).extract_info('https://www.youtube.com/watch?v=jNQXAC9IVRw', download=False)['title'])"
```

### 这条路的代价（务必知道）

- **本机必须在线且梯子开着**。本机休眠、断网、梯子关掉 → 服务器立刻失去外网能力。
- 批量跑批时**隧道断 = 成片失败**。实测踩过一次：隧道在 13:30 中断，
  产生 **99 条"字幕不可得"**失败记录（任务没坏，能救回约 40%，但要重跑）。
- 所以：**跑批期间别关本机**。要长期无人值守，请看下面的替代方案。

### 三个具体坑（都踩过）

| 坑 | 现象 | 原因 / 解法 |
|---|---|---|
| **旧隧道占住端口** | 新隧道起不来，或请求打到奇怪的服务上 | Windows 下结束"作业"杀不掉 ssh 子进程，旧隧道还在占 17890。必须按 PID `Stop-Process`（PowerShell）/ `taskkill`（cmd）清干净，或换一个端口号 |
| **打到哑服务** | 返回 `501 Unsupported method ('CONNECT')` | 这个字符串是 **Python `http.server` 的标志性回话**——说明 CONNECT 请求打到了某个本地静态服务，而不是真代理。此时"隧道通了"是假象，端口被别的进程占了 |
| **代理只对内网生效** | 服务器上 `curl` 通、`yt-dlp` 不通 | 确认导出的是 `ECHONOTES_YT_PROXY`（不是 `HTTP_PROXY`），并确认是 `http://` 而不是 `socks5://`（当前只支持 HTTP 代理） |

### 一个容易被忽略的设计：LLM 走直连，不穿梯子

`ech_config.py` 在启用代理时会自动把 LLM 域名加进 `NO_PROXY`：

```python
os.environ["NO_PROXY"] = "api.deepseek.com,127.0.0.1,localhost"
```

也就是说——**梯子只负责 YouTube / yt-dlp，LLM 调用始终直连**。这是刻意的：
否则隧道一断，连"润色"都做不了，而国内直连 DeepSeek 本来就通。
如果你换了别的 LLM 端点，记得把域名也加进 `NO_PROXY`，否则会出现"视频能下、笔记写不出来"的怪现象。

### 替代方案：海外 VPS 直连

如果你有海外 VPS，就没必要搭隧道了——它本来就能直连 YouTube：

```bash
export YT_PROXY=direct        # 显式关闭代理，直连
```

VPS 路线见 [Ech_youtube/SERVER.md](../Ech_youtube/SERVER.md)。

## 2. 字幕优先：能不下音频就不下

YouTube 侧有一条专门的省流路径：**优先用官方字幕，只有拿不到字幕才回退 ASR**。

```
yt-dlp 拉英文字幕(VTT) ──▶ subs_to_transcript.py ──▶ transcript.json ──▶ 下游全部复用
        │                                              （与 whisper 输出同构）
        └ 拿不到字幕 ──▶ 下载音频 ──▶ faster-whisper ASR ──▶ transcript.json
```

为什么重要：**音频要 100MB 级/期、全量 ~50GB 上传**，而字幕只有 KB 级。
实测 447 期里只有 **4 期**因为确实没有英文字幕才回退到 ASR。

**关键设计**：`transcript.json` 是整条管线的枢纽。只要造出这个格式，
下游的「说话人标注 → 翻译 → 渲染」全部复用，**不关心它是字幕来的还是 ASR 来的**。

## 3. LLM 配额：这一节能帮你省几百块

批量跑批时，LLM 是**最容易先崩的一环**，而且不同平台的"上限"**维度根本不一样**：

| 计费类型 | 卡的维度 | 撞墙时你会看到 | 本项目实测 |
|---|---|---|---|
| 包月订阅（Coding Plan） | **调用次数**（按时间窗，如 5 小时内的 prompts 数） | `429` + 错误码 `1308 已达到 5 小时的使用上限` | 8 工人 **几分钟**打光一个窗口 |
| Token 包 | **token 总量** | `Your token-plan 1-week quota has been exhausted` | 8 工人**两天**烧穿整周配额 |
| 按量付费（OpenRouter 等） | **钱**（按 token 计价，无次数上限） | 余额不足 | 447 期约 **$1~2** |
| 免费档（Gemini / GLM-Flash 等） | **请求次数/天 + 每分钟** | `429` 限流 | 免费档日额度 ≈ 250~500 次，**远不够** |

**本项目的负载是"双高"**（实测基线）：

```
单期  ≈  95 次调用  +  14 万 token
全量  ≈  4.2 万次调用 +  6300 万 token      （447 期）
```

所以两种极端都会撞墙：**订阅制按次数给，而我们的调用次数密度极高**（8 工人每 5 小时要 4800 次，
订阅制的窗口只有几百次量级，差一个数量级）。

### 工程上的应对（已在管线里实现）

1. **密钥轮换**：runner 支持配置多把 Key，按工人/按请求轮转，把限额摊到多把钥匙上。
2. **配额类错误快速失败**：`polish` 模块识别"欠费/配额耗尽"类**终局错误**后立即失败，
   不做无意义重试——**否则会空烧 300 秒 × 5 次**。
3. **分级降级链**：主力模型撞限流后自动切备用端点。
4. **409/429 长冷却**：区别于普通错误，走更长的退避。

> 一句话总结：**订阅制看次数、token 包看 token、按量付费看钱。**
> 多工人批跑前，先算清"你的额度是按什么维度给的"，再决定开几个工人。

## 4. 跑完之后：产物归档与回拉

**服务器侧归档**（跑完由 `archive.py` 生成）：

```
~/Wholeworks/<你的文件夹>/
├── Ech_bilibili/          # B 站管线
├── Ech_youtube/           # YouTube 管线
└── 笔记归档/
    ├── LexFridman/        # 447 篇 html + index.html 卡片墙 + README.md + 归档报告.md
    └── <创作者>/
```

**回拉本机**（增量覆盖，可反复跑）：

```bash
scp -q -r <server>:~/Wholeworks/<你的文件夹>/笔记归档/. ./视频笔记/
```

实测：LexFridman 320MB / 阿卡迪萨 13MB，几分钟拉完。

## 5. 夸克网盘上传：中文目录名会 500（根因已定位）

如果你要把产物镜像到夸克网盘（经本机 **OpenList**），**目录名不要用中文**。

### 现象

```
mkdir  /quark/播客笔记              →  200  ✅（看起来成功了，根目录也能列出这个名字）
list   /quark/播客笔记              →  500  ❌ object not found（refresh=true 也无效）
list   /quark/播客笔记/LexFridman    →  500  ❌
list   /quark/zz-ascii-test/sub     →  200  ✅（纯 ASCII，同样嵌套两层，正常）
```

### 根因

**OpenList 的夸克驱动无法解析含中文的目录路径。**

注意区分——**中文*文件名*完全正常**：`01-一个有仇必报的社恐解开了自己的封印.html`
上传后返回 200 且回列名字完整。**只有目录名不能是中文。**

### 修法

云端目录名一律用 ASCII，中文集合名做一层映射：

```python
QUARK_ROOT = '/quark/podcast-notes'                  # 不要用中文
CLOUD_NAME = {'LexFridman': 'LexFridman', '阿卡迪萨': 'Akadisa'}
```

### 同一套工具另踩的两个坑

| 坑 | 现象 | 根因 |
|---|---|---|
| **开机自启脚本直接死** | VBS 自启无效，服务根本没起来 | VBS 里写了**中文注释**，注释行**吃掉了换行**，导致下一行 `Set ws = ...` 被并进注释里。**自启脚本一律纯 ASCII** |
| **计划任务一启动就崩** | 任务返回错误但日志为空 | `pythonw.exe`（无控制台）下 **`sys.stdout is None`**，任何 `io.TextIOWrapper(sys.stdout.buffer, ...)` 会直接抛 `AttributeError`。包装 stdout 前必须 `if sys.stdout is not None` |

## 6. 密钥安全（新手最容易在这里翻车）

- **仓库里永远没有任何真实密钥。** 所有 Key 只从 **环境变量** 或 **本机密钥文件** 读取，
  `.gitignore` 已显式排除 `.env`、密码书、cookie、sqlite。
- 想配置：`cp .env.example .env` 然后填 `DEEPSEEK_API_KEY` 等（`.env` 不入库）。
- 每个 Key 用在哪、为什么选这个模型、去哪申请，见 [API_SETUP.md](API_SETUP.md)。
- **把密钥传到服务器上时**：用 `scp` 传文件或写进服务器自己的 `.bashrc`，
  不要在命令行里 `export KEY=xxx` 之后再截图/贴日志——那会直接进聊天记录和 shell history。

## 7. 换机器 / 换服务器：照这张表过一遍

| 步骤 | 命令 / 动作 |
|---|---|
| 1. 装环境 | `python scripts/install.py`（装 ffmpeg + 建 venv + 装依赖 + 自检） |
| 2. 体检 | `python scripts/check_env.py`（逐项 `[OK]/[WARN]/[FAIL]`，缺什么给什么修法） |
| 3. 配代理 | 国内机器：`ECHONOTES_YT_PROXY=http://127.0.0.1:17890`（或你选的路子）；海外机器：`direct` |
| 4. 传模型 | whisper 模型 464MB，**两平台共享同一份**，`scp -r` 拷贝一次即可，别各下一份 |
| 5. 起隧道 | 本机 `ssh -N -R 17890:127.0.0.1:12000 <user>@<server>`，并验证服务器侧 200 |
| 6. 试跑单期 | 先跑 1 期，确认产物正确，**再放批量**（见 README"先测试再定"） |
| 7. 放批量 | 先小并发（`WORKERS=2`）验证机制，再放全量 |
| 8. 收产物 | `scp -r` 拉回归档，核对 `归档报告.md` 的"缺失"栏是否为 0 |

> **本项目的立场**：不把环境问题甩给使用者。上面 1、2、6 步都有脚本兜底，
> 缺依赖时管线会**在启动阶段**用退出码 2 拦下来并给出人话提示，不会跑到一半才甩 traceback。
