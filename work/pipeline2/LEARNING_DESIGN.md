# 学习目标与理解批注的生成规则

设计日期：2026-09-18。适用于不同数学、工程或混合课程；不把李群课程的主题写死到通用提示词中。

## 学习方向的来源

从已有完整转写、视觉知识块和时间索引生成课程地图。学习者背景没有给出时，前置知识是建议而非已知画像。

每个目标包含一个可观察产出和检验问题，分基础、深入和迁移三层。模型需解释为何选择当前视角，并生成课程专属 `writing_brief`，后续各单元复用。这份指导可以修改、复查并进入缓存指纹，不是临时拼接的一句“请深入理解”。

## 数学视角

从动机和例子进入精确定义，检查条件的必要性、特殊情形、反例、证明策略，再回到经严格推理修正的直觉。

这一设计参考：

- Terence Tao, *There’s more to mathematics than rigour and proofs*：
  https://terrytao.wordpress.com/career-advice/theres-more-to-mathematics-than-rigour-and-proofs/
  借鉴直觉、严格性与经严格性检验后的直觉相互配合的思路。
- Terence Tao, *Ask yourself dumb questions – and answer them!*：
  https://terrytao.wordpress.com/career-advice/ask-yourself-dumb-questions-and-answer-them/
  借鉴主动考察假设、逆命题、退化情形和论证中条件用途的学习方法。

这些是教学设计参考，不是模仿数学家口吻。生成内容不得附上未经核实的名言或声称数学家认可某个解释。“高阶视角”只有能解释当前困难才使用，不能任意引入范畴论等新术语。

## 工程视角

本项目采用的教学组织建议：实际任务 → 观测量 → 模型与假设 → 方法 → 实现约定 → 误差和失效边界。

根据内容选择量纲、坐标约定、左右乘、离散化误差、计算成本等检查项。对概念课不强塞代码，对证明课不强塞应用。新增技术案例或条件必须标记为编辑补充。

## 提示词与输出契约

- `prompts/learning-plan.md`：课程内容 → 目标 + 检验问题 + 专属写作指导 + 连续学习单元。
- `prompts/study-unit.md`：单元证据 + 全课目标 + 前文衔接 → 忠实讲解、来源笔记、补充推导、
  洞见批注（每条含非显然论断及边界）、自测、单元符号小结、疑点。
- `prompts/study-deepen.md`：出版级深化遍——补全跳步推导、加最小可算例子、深化批注；
  source 证据 ID 必须逐条保留，代码机械校验课堂来源不丢失。
- `prompts/study-review.md`：对成稿逐单元审查数学等式、几何直觉、模型假设及来源/补充边界，记录修订理由。
- `prompts/study-style.md`：付印前主编遍——只允许改写各单元批注，统一全书术语与口吻。
- `prompts/concept-map.md` + `concept_map.py`：课程概念地图。规划模型产出概念节点
  （定义/定理/方法/应用四类）与带关系标签的有向边；节点按学习单元分列，
  Python 蛇形布局并生成 TikZ，印在目录前。模型无排版自由度，结构校验限定规模与端点。
- `study.py`：校验转写顺序/覆盖、代表帧时间、来源ID、原课与补充标记和展示公式语法；
  编排 初稿 → 深化 → 数学审校 → 文风统一 四道带缓存工序。
- `study_render.py`：卡片编排（蓝绿紫红色块），一份连续PDF，不生成全量截图附录。
- `study_render_book.py`：出版编排——连续行文为主，〔补充〕标题承载补充标记，
  批注为绿色竖线段，思考题与疑点弱化为节末小字；颜色法律与卡片版一致。

生成的学习目标不等于测量过用户能力；格式校验、源码引用校验及模型审校均不等于数学正确性证明。
深化与文风遍生成的补充内容仍是编辑解释，未经独立证明。来源字段不能自动保证每句话都忠实，仍需内容复核。

## 排版选择

使用本机 TeX Live 提供的 `ctexart`、`amsmath`、`tcolorbox`、`fancyhdr`、`hyperref`。
浅蓝表示课堂内容，浅绿表示编辑补充，紫色表示自测，浅红表示疑点。色块可跨页，公式保持可读字号，图片按单元选取并附时间及索引。

检索到的 Elegant Notebook 模板提供主题和笔记环境设计，可作为视觉参考：
https://github.com/xinli12/elegant-notebook-latex

没有确认名为“beautiful notebook”的特定包；本实现没有下载或复制未知模板。采用自己的轻量样式，避免整套模板依赖和字体冲突。
