DESIGN PROPOSAL · 分管线设计

三类视频形态，三条分管线
口播观点 / 课程讲义 / 实操复刻 —— 共用感知底座的内容形态分层设计

基于源码级调研结论，把"视频观看 agent"按内容形态拆成三条管线：信息所在的模态不同，处理路径、难点和输出物完全不同。本方案给出每条管线的设计、现有轮子与可行性评级。

📅 2026-09-17📌 承接《源码级技术调研报告》🎯 目标：让三类视频各自有一条能落地的完整链路
① 三类形态的本质差异 ② 总架构：共用底座 + 三个分叉 ③ 管线一：口播/观点类 ④ 管线二：课程 → LaTeX 讲义 ⑤ 管线三：实操教程 → 复刻+实验报告 ⑥ 可行性评级与路线图

1三类形态的本质差异

分型的依据不是视频题材，而是"信息到底装在哪个模态里、输出物长什么样、怎么验收"。这决定了三条管线的每一段都不同。

🎙️ 类型一 · 口播/观点📐 类型二 · 课程/讲座🛠️ 类型三 · 实操教程
典型内容播客、政治/时事观点、小说推荐数学讲座、系统课程PS/绘画教程、AI提示词实验、剪辑、游戏技术美术、计算机开发
信息载体几乎全在音频（画面常是装饰性 B-roll）音频讲解 + 板书/PPT 画面（公式、推导、图表在画面上）操作序列（屏幕动作、参数设置、工具切换，口头只讲一半）
画面重要性低，字幕直取即可覆盖 95%高——丢掉画面=丢掉公式和图表极高——丢掉画面=丢掉操作本身
输出物观点梳理文/推文、论点结构、金句、时间轴索引LaTeX 讲义（定义-定理-推导-例题），像好学生的完整笔记操作步骤讲义 + 实验报告 + 复刻产物（可运行的项目/图/工程文件）
验收标准覆盖率高、立场还原准公式可编译、推导可复算、与视频可互查产物能跑/能开/能看，步骤能跟着做通
核心难点长音频的写作质量（已基本解决）公式 OCR + 板书帧去重 + 讲义结构化步骤提取 + agent 真实执行 + 产物验证
难度★☆☆ 现有轮子够用★★☆ 轮子成熟但需拼装★★★ 前沿，需分级降级策略
为什么必须分型：对类型一跑多模态抽帧是浪费钱（画面没信息）；对类型二只靠字幕会丢掉全部公式（字幕读不出数学）；对类型三只做"笔记"没意义——你要的是复刻产物。一套管线包打天下的方案，在这三类上必然两类是残废。

🖼️

场景感知抽帧 + actual_t 对齐 + 补帧闭环

分流：内容分型器
首轮粗看（元数据+抽样帧+转写开头）→ 判定类型 → 路由
📝
① 口播分线
纯文本管线：转写 → 观点结构化 → 写作模型成文（不抽帧或极少抽帧）
∑
② 课程分线
板书帧检测去重 → 公式OCR(Pix2Text) → LaTeX 讲义 map-reduce
🛠️
③ 实操分线
屏幕OCR+帧差 → 操作序列JSON → agent按环境分级执行 → 实验报告+产物验证

分型器设计：成本低——只看三样东西：①元数据/标题/UP主分类；②转写前 500 字的语言特征（"今天我们聊聊"vs"我们来证明"vs"打开软件"）；③均匀抽 8 帧的画面特征（人像 vs 板书 vs 软件界面）。规则+小模型即可，不必上大模型。

3管线一 · 口播/观点类：纯文本管线

⬇️
字幕直取
B站CC/AI字幕，跳过视频流下载（省时省钱90%）
🧹
文本清洗
滚动重复去重、语气词归并、说话人分离（多人播客）
🧩
观点结构化
map：分段提取"论点-论据-例子-立场"四元组
✍️
写作输出
reduce：按文体模板成文（推文/读书笔记/观点综述）
✓

现状：直接可做。这是上次调研里所有"纯字幕流"项目已验证的路径，80% 覆盖率规则（video-to-article-skill）+ map-reduce 分段（let-ai）搬过来即可。

＋

补充设计 1 · 说话人分离：多人播客需要区分"谁在说"。轮子：pyannote.audio 或 faster-whisper 的词级时间戳 + 简单聚类；输出转写时标注 Speaker A/B。

＋

补充设计 2 · 观点类特殊处理：时事观点视频的输出物要加一层「立场还原」约束——区分"UP主的论点"和"整理者的转述"，写作 prompt 里禁止把转述写成事实（沿用 let-ai 的证据边界规则：转写里没有的不许编）。

＋

补充设计 3 · 小说推荐类：输出结构应是结构化书单（书名/作者/推荐理由/时间戳），可以直接规则化提取，产物可入库（以后做"推荐聚合"）。

🎙️
转写
同共用层；数学术语需热词表纠正（whisper 对"特征值"这类词容易错）
🖼️
板书帧检测
场景检测变体：画面静止久 + 文字密度高 = 讲义页；感知哈希去重
∑

Pix2Text / LaTeX_OCR_PRO 把板书公式转 LaTeX；多模态模型兜底
🧩
map 分段笔记
每 10-15 分钟：「讲解转写 + 对应板书页」→ 结构化片段（定义/定理/推导/例题）
📄

合并 → LaTeX 模板 → 编译 PDF；公式逐条与原帧对照校验

关键环节 1：板书/PPT 帧的检测与去重

课程视频的画面 90% 时间是静止的讲义页，直接均匀抽帧会拿到几百张重复图。策略：

1

感知哈希去重：对候选帧算 pHash（imagehash 库），汉明距离 < 阈值视为同一页，只保留一张——板书页平均可以从 100 帧压到 10-20 页。watch-skill 项目（本地视频索引）已用同类"perceptual-hash dedup"方案。

2

文字密度启发：OCR 前用轻量检测（边缘密度/连通域数量）判断"这帧有没有板书"，人像特写直接丢弃。

3

关键帧页 = 讲义资产：去重后的板书页按时间戳归档，讲义里每页嵌入引用（t=12:34 可回看），这是"好学生笔记"和普通总结的核心差别。

关键环节 2：公式识别的现成轮子

项目Stars能力选型建议
breezedeus/Pix2Text3.2k版面+表格+公式+文本一体化识别，输出 LaTeX首选：一个工具同时处理文字和公式，MIT 协议
LinXueyuanStdio/LaTeX_OCR_PRO1.3k手写+印刷公式，中英文，支持符号推导（LaTeX AST）手写板书场景备选

关键环节 3：讲义的"好学生规范"与校验

# LaTeX 讲义的结构模板（每讲）
\section{定义}[t=05:12]        % 每个结构块携带视频时间戳
\section{定理与证明}[t=18:40]   % 推导步骤逐条可回看
\section{例题}[t=32:05]        % 板书原页作为 figure 嵌入

# 校验闭环（保证"可阅读"不等于"能编译就行"）
1. pdflatex 编译零 error —— 公式语法校验
2. 逐条公式与原板书帧对照（多模态模型交叉验证）
3. 术语一致性表：全篇符号定义唯一（讲义最容易烂在符号混乱上）
参考项目：lachlanchen/Video2Book 已验证"视频合集→转写→LaTeX/PDF 讲义"完整 pipeline 可行；byxshr/video-render-pdf-skills 把同样的事做成了 skill。它们都只处理音频、不处理板书画面——加画面通道就是我们的差异点。

5管线三 · 实操教程：看懂 → 做出 → 写报告

这是三种里最激进的：agent 不只是"看懂"，还要按教程实际操作并交付复刻作品。调研发现这个方向已有先行者，但完整闭环（复刻+实验报告）仍无人做全。

先分情况：不是所有教程都能"真复刻"

可执行性等级环境例子复刻策略可行性
A可编程环境代码/CLI/配置文件/提示词Python/前端教程、AI 提示词实验、ffmpeg 命令、Shaderagent 真执行：建工作区、装依赖、逐步复现、跑测试高，先做这块
BGUI 软件操作PS/剪辑软件/Blender 等PS 调色步骤、Pr 剪辑、游戏引擎操作半复刻：提取精确操作步骤手册；GUI agent 辅助执行（实验性）；或人机协作——agent 指导、人操作、agent 验证截图中，步骤手册稳定可用
C手艺/创作类手绘/审美驱动绘画教程、构图讲解讲义+练习：完整技法拆解讲义 + 分步练习任务单；可用代码生成器辅助复现特定效果低，产出讲义即可
务实建议：v1 只做 A 级环境（含游戏技术美术里的 Shader/代码部分、提示词实验、开发教程）——这是 agent 能 100% 自主完成的闭环；B 级先交付"精确操作手册"（步骤+参数+时间戳截图），GUI 复刻作为 v2 实验特性。

核心环节 1：操作序列提取（帧+屏幕OCR+转写 → 步骤 JSON）

教程视频的口头讲解和屏幕操作各说一半，必须三路融合。参考 sonpiaz/watch-cli 的已验证做法——它的定位就是"观看这个视频并构建其中展示的项目"：

# watch-cli 的实际用法（agent 收到的素材包）
$ watch https://youtube.com/watch?v=TUTORIAL 16    # 参数=帧数
VIDEO: /tmp/dl-video/abc123.mp4
DURATION: 1847
FRAMES: frame_01.jpg  # 项目文件夹结构
FRAMES: frame_02.jpg  # package.json 内容
FRAMES: frame_03.jpg  # App.tsx 源码
FRAMES: frame_04.jpg  # 终端里的 npm install
TRANSCRIPT: "先创建 React 项目，然后安装依赖……"
# agent 处理：看结构→建目录 / 读依赖→写 package.json / 照屏代码→实现 / 转录补口头说明
# 结果：与教程一致的可运行项目

我们的版本在此基础上结构化升级——每一步输出为可校验的操作记录：

{
  "step": 7,
  "action": "run_command",          // install_pkg / edit_file / set_param / ui_click / draw_stroke ...
  "detail": "npm install three @types/three",
  "evidence_t": "14:22",           // 步骤依据的帧/转写时间戳
  "expected": "node_modules 出现 three 包",
  "verify": "ls node_modules/three"  // 执行后的验证命令/检查方式
}
1

屏幕 OCR 是 A/B 级的关键通道：终端命令、代码、参数面板上的数值都在屏幕文字里，PaddleOCR/Tesseract 或直接让多模态模型读帧（效果好但贵），与转写按时间戳对齐。

2

帧密度按内容自适应：操作密集段（画面变化快）加密抽帧，讲解段放稀——沿用场景检测，对"屏幕录制"类视频阈值要调低（窗口切换就是关键事件）。

核心环节 2：agent 执行与实验报告

📦
环境准备
建隔离工作区（venv/临时目录），按步骤0安装依赖
▶️
逐步执行
按操作序列 JSON 复现，每步跑 verify，失败→回看对应帧/转写纠错重试
🧪
产物验证
代码→跑测试；图像→与原视频帧对比；工程文件→能否打开
📋
实验报告
偏差记录、踩坑、修复过程、最终产物截图/路径
# 实验报告模板（与讲义配套交付）
## 1. 教程信息          # 标题/UP主/时长/环境假设
## 2. 复现环境          # agent 实际用的 OS/依赖版本（与教程差异声明）
## 3. 步骤执行记录       # ✅32步 / ⚠️3步有偏差（列偏差与原因）/ ❌1步失败（原因分析）
## 4. 偏差与踩坑        # 教程没提但实际遇到的（版本差异/平台差异），这是报告的价值核心
## 5. 最终产物          # 复刻作品路径 + 截图 + 与原视频效果对照图
## 6. 结论与改进        # 教程本身的问题（跳步/过时），给 UP 主的"勘误"

失败处理是设计核心：某步 verify 失败时，agent 回到对应时间戳看帧+转写，自查是"漏了前置步骤"还是"环境差异"，重试最多 2 次——这直接复用 let-ai-read-video 的补帧闭环模式（insufficient → 定向补证据 → 重验证），只是补的从"帧"变成"执行上下文"。

生态现状：这个方向刚刚起步，正是切入点

项目定位与我们目标的差距
sonpiaz/watch-cli 最对口CLI 把"帧+转录"打包喂给 agent，演示了"看视频建项目"全流程无操作序列结构化、无失败闭环、无实验报告、YouTube 为主
oxbshw/watch-skill本地视频索引（SQLite+向量检索）、置信度评分、低成本升级策略（密采样→放大重OCR→引用前验证）定位是"看懂"，不做执行
Video-Use 23k★Browser-Use 姊妹项目，帧采样+多模态问答/剪辑指令视频理解通用库，无教程复刻概念
学术线：COIN / CrossTask / YouCook2程序性视频步骤标注数据集（步骤定位/先后顺序学习）数据集而非可用工具，但步骤建模思路可借鉴
GUI agent 线（OSWorld / CogAgent 等）B 级环境的屏幕操作执行器通用 GUI 操作，不懂"教程上下文"，成本高

结论："提取操作序列 → 分级执行 → 产物验证 → 实验报告"这个完整闭环没有现成项目，但每个零件（watch-cli 的素材包、watch-skill 的置信度策略、GUI agent 的执行器、let-ai 的失败闭环模式）都存在。这是三条管线里差异化最大、也最值得投入的一条。

🚀 建议实施顺序

P0

先把共用底座跑通（获取+语音+基础抽帧+分型器），用一个真实 B 站视频验证三路分流正确。

P1

管线一上线——最快见效，且写作层成果（文体模板、覆盖率检查）直接被管线二三复用。

P2

管线二接公式 OCR，拿一集数学讲座做端到端验证（编译通过+公式对照）。

P3

管线三从 A 级起步：选一个"跟做型"开发教程（如 three.js/WebGL 小项目），跑通"操作序列→执行→验证→报告"最小闭环，再逐步扩 B 级。

本方案承接 2026-09-16《源码级技术调研报告》。新增调研：watch-cli（看视频建项目已验证案例）、watch-skill（本地视频索引+置信度）、Video-Use、Pix2Text/LaTeX_OCR_PRO/Texo（公式OCR）、Video2Book（视频→LaTeX讲义 pipeline）。可执行性分级（A/B/C）为本方案的核心设计决策，决定了管线三"真复刻/半复刻/讲义"三档产出。
